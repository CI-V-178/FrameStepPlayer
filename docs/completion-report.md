## この指示書から外れた判断と理由

- Node 22系（22.12以上）を採用。既定のNode 18では要件を満たさず、更新したテスト依存関係にも対応するため。`.nvmrc` とプロジェクト内Nodeを用意。
- E2EのサーバーはIPv6ループバックの5174番。WSL環境で未使用IPv4ポートへの接続がタイムアウトするため。
- SW経由のブラウザ試験は、指示書で認められたBlob代替経路で検証。SW自体は独立した単体テストを追加。
- 元から未追跡だったJO.mdは変更・コミットしていません。

## 既知の問題

実際のGoogleログイン、実Driveの権限・保存先、iPhoneでのSWストリーミングは未検証です。自動テストで確認した範囲に未解決の不具合はありません。

## ユーザーが行うこと

1. GCPのOAuthクライアントの「承認済みのJavaScript生成元」に `http://localhost:5173` と公開URLを追加。
2. OAuth同意画面（テスト中）のテストユーザーに自分のアカウントを追加。Drive APIとGoogle Picker APIを有効化。
3. 後で提供する設定をローカルの `.env` に設定。Vercelへリポジトリの `mvp` ブランチを取り込み、環境変数 `VITE_GOOGLE_CLIENT_ID` / `VITE_GOOGLE_API_KEY` / `VITE_GOOGLE_APP_ID` を設定してデプロイ。ビルドは `npm run build`、出力先は `dist`。
4. 実機で以下を確認。

## 実機での確認項目

- iPhone Safari：Driveの動画が全部ダウンロードされる前に再生が始まるか。始まらなければBlob代替経路で再生されるか。
- iPhone Safari：±1f、長押しによる連続移動、長押しメニューが出ないこと。
- 動画と同じフォルダに.memo.vttができるか。作成できなければ「FrameStep メモ」フォルダへ保存されるか。
- 別の端末で同じ動画を開いて同じメモが出るか。
